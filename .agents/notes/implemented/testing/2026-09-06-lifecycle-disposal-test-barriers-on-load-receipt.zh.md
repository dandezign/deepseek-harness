# Agent Note：生命周期弃用测试以加载接收为屏障，而不是依赖固定睡眠

Status: implemented

[English](2026-09-06-lifecycle-disposal-test-barriers-on-load-receipt.md) | 中文

## 问题

`stops driving the endpoint once disposed mid-load` 在完整套件下失败过一次（`expected 1 to be undefined`），而每次隔离运行都通过。该测试在固定 40ms 睡眠后弃用管理器，并在弃用拒绝解决后立即捕获 `loadCount`。mock 在请求接收时递增计数器，因此捕获与一个特定事件竞争：恰好在 `dispose()` 之前已发出的加载 POST 已经在线路上，而 mock 的处理器——计数增量的归属方——按服务端自己的 I/O 节奏运行。负载下，这次落地发生在捕获之后：计数读到 `undefined`，在随后的稳定窗口内涨到 1，等值断言便由一次弃用从未引发请求而触发。

## 决策

mock 路由器拥有请求接收，因此它现在发布它：`loadReceived(model)` 在至少一条该模型的加载 POST 已被接收并计数后解决（若已发生则立即解决）。测试在该接收屏障之后再弃用，并把捕获的计数显式钉在 `1`。屏障之后计数在构造上即已稳定——生命周期每轮等待只发出一条加载 POST，mock 在整个窗口内把模型保持在 `loading`，不会打开重发路径，且管理器在弃用后能发出的任何 fetch 都会经作用域中止而拒绝——于是余下的稳定窗口与等值断言恰好守护它所声称的回归：弃用后发出的加载 POST。

固定的 40ms 弃用前睡眠已被移除。它从来不是就绪信号：在安静主机上它在 POST 被计数之后很久才弃用，在负载下它在分发中途弃用——这正是上面的失败。

## 已考虑的替代方案

**把捕获放到更长的睡眠之后。** 否决：它加宽窗口却没有指名所等待的状态；在 40ms 处压断测试的同一负载诱导延迟，在任何固定值处同样能压断。

**轮询计数器直到不再变化，再捕获。** 否决：“N ms 内无变化”是披着 promise 外衣的睡眠启发式；mock 可以直接陈述接收。

**改为断言生命周期自身发出的请求日志，而不是服务端计数。** 延期：它需要在 `ModelLifecycle` 上增加一个其他消费方都不需要的注入点；服务端接收才是拥有的、可观察的信号。

## 验证

阴性对照：把 `closed.abort` 从 `dispose()` 中注释掉后，测试在 `rejects` 断言上失败（无 `ABORTED`），证明守护仍然对其存在的回归生效。修复后的规格 5×23 次通过，包泳道 3×50 次通过，拓扑与当初闪失的拓扑一致；产品源码未被触及（对照的回滚为字节级一致）。

## 后果

完整套件拓扑失去这一闪失。屏障还消除了一次空洞通过：此前若弃用落在第一条 POST 之前，测试什么也没有验证；现在测试可证明地在加载进行中弃用。
